# 产品设计与取舍

InterviewTwin让面试官通过对话了解赵家奇的经历、项目与判断方式，并让其他人无需编写Skill指令，也能创建自己的分身。使用一个通用Skill、独立人物资料及少量脚本，复用宿主的模型与文件能力。

| 模式 | 用户任务 | 关键约束 |
|---|---|---|
| 面试回答 | 选定人物、自然提问、连续追问及查看依据 | 只使用选定人物资料；历史、设计、离线验证与推演分开 |
| 创建分身 | 上传简历、试问纠错、确认内容与公开范围、导出 | 一份简历先生成最小知识；按需拆分；原件不丢失 |
| 维护更新 | 修订资料、同步原分发的能力与绑定人物 | 自建人物、草稿和旧快照保护；冲突停止；新会话核验 |
| 评测检测 | 运行人物专属题库、查看逐项判定与真实回答 | 自动评审不能代替本人确认或真人试用 |

少量资料可试问，确认后才形成可交付版本。内容准确、允许提供和授权发布是三个不同决定。上传或打包成功不等于正式入口可安装，文件更新成功不等于当前对话已加载新版。

首版选择Codex作为真实主验收环境；Claude Code和WorkBuddy提供目录适配及安装包，模型体验分别验收。通过Markdown知识与清单即可支持当前规模，不建设数据库、账号平台、复杂自动合并或跨宿主热刷新。

默认安装跟随原仓库默认分支，固定tag/commit仅作为明确锁定选项。普通更新同步能力及绑定人物；发现正式文件有本地修改时停止，不猜测覆盖。保留来源和内容指纹，按实际版本报告结果。

质量先看事实与贡献边界，再看回答是否直接、自然、解释判断依据。9分是内部迭代目标；当前受检题目上的自动得分不能推导为任意问题都达9分。
