# InterviewTwin 技术架构

## 普通 Skill 安装入口（0.1.22，本地未发布）

本轮不改变人物内容与面试回答规则。完整 `skills/interviewtwin/` 已携带审核人物的只读初始化材料；通用安装器只复制该目录即可。安装收尾或首次使用由Skill调用bootstrap离线初始化到工作区people，无须用户再执行产品安装命令。更新沿用原安装器，然后显式同步绑定人物；只升级能力时保留人物版本。草稿、自建人物、原件与旧快照在Skill外保留。

通用更新的能力替换和人物同步是两个阶段，失败分别报告，不宣称跨工具原子性。旧专用安装器仍可用。当前有效入口以 [INSTALL.md](../INSTALL.md) 为准；以下旧版本安装段落只作历史记录。


## 安装与更新（2026-10-25）

当前合并交付为能力0.1.21、人物1.1.5及安装器0.2.0，统一从正式GitHub仓库获取。

完整 Git 副本经来源、commit与干净状态核验后直接安装，不再次下载 ZIP。只有安装器时优先 Git 获取一次；ZIP 为明确备用路径，优先系统 curl。更新先检查原来源 commit；未变且安装内容完整时跳过完整下载，有变化才获取一次。资料保护、固定ref与会话加载边界保持不变。

安装器脚本独立保留当前经审核版本与哈希，不直接执行下载包内工具。旧入口迁移需读取最新 INSTALL 并审核工具；新入口日常更新使用保留工具。具体命令、失败分类与停止条件以 [INSTALL.md](../INSTALL.md) 为准。

本轮文件机制验证与真实 Agent 聊天验证分别报告，见 [交付验证结论](交付评测结论.md)。不得把目录适配测试称为 Cursor/其他宿主聊天安装已通过。

## 本地收尾约定（0.1.15）

普通一句话安装默认读取原仓库HEAD，即默认分支；普通更新同步同一来源的能力与绑定人物（包括审核原件），保留自建人物、草稿和旧快照。明确锁定tag/commit后不会自动跳到新版本。指定分支则继续该分支，不擅自换源。维护者应只将经过审核的交付放入默认分支。报告更新前后实际版本及是否变化；文件更新与新会话生效分别验收。

自动评测支持任意已安装人物：用`--person`选择人物标识，`--cases`提供对应题库。题库声明人物姓名和标识，独立评审读取受检当前快照；人物、版本或内容哈希不一致即停止。只把问题传入被测会话，参考要点和评审知识在外部，不能用赵家奇的答案评价其他人物。完整执行器位于交付项目，最小安装包不含答案。

新受检能力为0.1.15，赵家奇资料1.1.0，本轮没有修改个人事实或简历。实际结果见收尾报告；自动评分、Markdown解析、本人相似度、真人复用和跨宿主验收独立记录。暂不发布GitHub、不发送邮件。


## 最小知识与按需拆分（本轮生效）

单份简历默认先生成knowledge/profile.md；内容按实际资料组织，缺失栏目省略，不生成固定六份或空文件。至少有明确人物及一段可归属经历即可试问，事实缺口不得补造。原件独立存储。

新增内容先归入已有主题。项目形成可独立追问的完整主题、单独维护能减少重复时，再拆为projects/<id>.md；详细职业时间线可按需拆为career.md。profile.md保留简介与有效链接，不按字数强制拆分。长期风格经用户明确确认后可生成style.md，临时“短一点”等只影响当前对话。历史事实、设计方案、离线验证在内容中明确区分，不要求分别建文件。

拆分前后核对事实覆盖与来源，详细事实有主要维护位置，简介摘要同步；原件保持字节一致，旧版本与其他人物不得修改。新增口述材料原话归档，不将AI扩写冒充原件；冲突集中交用户确认。用户确认内容和范围，不需要选择文件名或手写JSON。

Agent负责语义整理，脚本不自动抽取或按固定模板拆分。draft输入为完整知识目录；新项目、风格加入时须带上所有保留文件，显式sources须包含全部保留原件。更新来源对应并重新取得所需确认，不把旧审核移植到新文件。现有schema 2与安装更新机制保持不变。

验收采用第二合成人物：一份简历生成最小知识，后续补充项目和长期风格后按需拆分；核对原件、既有事实、新增事实、来源对应、人物隔离、临时风格不持久化以及新会话实际读取。执行结果另记，不将规则存在等同验收通过。赵家奇现有六份资料不因新规则自动迁移。


## 原始资料与人物版本（本轮生效）

每个人物有自己的原件、草稿和确认版本。上传MD/TXT、PDF、PNG/JPG/JPEG/WebP时，先按原字节归档；粘贴文字保存为UTF-8 TXT再归档。每文件上限20MiB；不能读取的格式先说明，不能将上传成功当作解析成功。其他格式的原件目前不进入自动原件包，可在本人同意后转换成支持格式。原件与整理后的知识分别保留，不用AI改写内容替代用户原件。

- `people/<id>/sources/<sha256>/<原文件名>`：创建者本地归档。重复上传复用同字节对象，同名新文件保留为另一对象。原路径不写入分发清单。
- `people/<id>/authoring/draft/{knowledge,sources}`：知识与本次候选原件；修改知识时默认保留草稿已选原件，明确选择空列表才排除。`source-links.json`记录已核对的来源对应。
- `people/<id>/releases/<version>/{knowledge,sources,manifest.json}`：只包含当前指纹经内容确认和披露确认的文件。原件审核的是文件版本及允许提供的内容，不等于自动认定其中每句都正确。
- GitHub/本地分发源仍为`profiles/<id>/`，安装后进入人物的`releases/`；作者的本地归档不会被整体同步给接收者。通用Skill目录不保存人物简历。

默认面试读取知识，查看简历/依据时显式读取当前人物当前版本的`sources/`。来源对应只是证据关联，不意味着整份知识都来自简历；未覆盖的历史理由不能补造。原件和知识存在冲突时停止认领冲突结论，回到创建者确认，不在接收者面试中自动重写知识。

内容确认、披露确认、实际发布仍独立。未审核原件默认排除，界面必须显示实际纳入/排除列表。被排除的原件名称和本地路径不进入分发来源对应。文件或来源对应变化后，相关审核不能自动沿用。

普通更新整体更新原来源的能力和绑定人物快照，包括随包简历。先核验、再切换版本指针；旧版原件、本地归档、草稿和其他人物不覆盖。正式快照里的简历被本地修改时停止更新；失败时恢复原指针并保留原件。只升级能力时完全不写人物文件。新会话实际读取新版后才报告使用生效。

本轮暂停GitHub发布，不发邮件。公开授权不等于已上传；本地验收不能冒充正式链接验收。

## 人物schema与旧版迁移

人物schema 2沿用`files`完整SHA256清单，同时允许`knowledge/*.md`和`sources/`中受支持的原件；`source_links`为知识路径到随包原件路径列表。清单与实际文件集合必须完全相等，快照摘要包含manifest和所有原件。schema 1纯知识包继续可读和安装，新增包使用schema 2。不是把原件全文塞入SKILL.md，也不新增数据库或账号系统。

安装器不改写创建者的`people/<id>/sources`归档，仅事务性安装整个版本目录。读取二进制原件时返回实际文件位置、哈希和“未解析”状态，交由宿主读取；Markdown/TXT返回原文。脚本没有OCR或PDF解析器。

0.1.12及更早的保留安装器不支持schema 2。首次迁移时Agent从用户已指定的原分发来源读取新版INSTALL并审核新版安装器，使用新版`scripts/get.py --update`完成迁移；不得运行旧工具失败后删除资料强行覆盖，也不得自动执行未经审核的下载脚本。0.1.13保留的新工具之后按普通一句话更新工作。不同宿主仍分别验收。


## 当前实现与证据

采用一个标准 Skill、独立人物资料和 Python 确定性脚本。Codex 是主验收环境；同一通用能力可按宿主安装目录分发。具体受检版本、实际运行和限制见[首版验收报告](首版验收报告.md)。本文件描述代码实现，不把实现存在当作全部验收通过。

此前四项原型计划收敛为安装/读取、创建/隔离、更新/保护、自动评测四条真实验证链路。旧计划中的概念字段以本版实际文件结构为准；未建设账号系统、数据库、向量服务或复杂工作流引擎。

## 安装与更新入口（0.1.13）

安装器在工作区保存 `.interviewtwin/installations/<host>.json`：能力来源、逐人物来源、能力版本及更新工具位置。GitHub 来源记录仓库、ref、下载指纹，本地包记录本地源路径。来源记录与人物指针、能力文件一起提交；提交失败恢复原记录。

安装工具的两份标准库脚本保留在 `.interviewtwin/installers/<内容哈希>/`，不进入人物目录或宿主 Skill 发现目录。后续 `get.py --update` 读取已保存来源，默认更新能力和 `distribution_profile` 绑定的原分发人物；`--no-profile` 才只升级能力。初始分发身份与逐人物来源独立记录，导入第二人不改变绑定；旧记录仅在同源人物唯一时迁移。第二人物导入不偷换原能力来源；不同来源人物需使用自己的明确入口。不做静默换源或复杂合并。

固定 tag/commit 的更新不移动到新版本；HEAD/分支跟踪来源变化。旧安装缺少记录时需从审核来源补装一次。没有 Python、网络或写入权限时如实停止；本地脚本通过不能替代宿主自然语言安装实测。权限被阻断时遵守宿主授权，不关闭沙箱。

当前原件验收见 `tests/results/sources-013/`；`tests/results/distribution-update-0112/`保留为旧版本证据。正式 GitHub 入口未发布，不视为已经通过远端安装验收。面试回答规则与人物知识未改。

## 职责分工

| 组成 | 实现职责 | 不承担的承诺 |
|---|---|---|
| 宿主 Agent | 理解请求、Skill发现、文件读取、模型推理、工具执行及权限控制 | 各宿主模型和UI行为不保证相同 |
| SKILL.md 与 references | 四模式选择、人物和事实边界、自然表达、创建审核及操作衔接 | 指令不能代替文件权限或现实身份认证 |
| twin.py | 人物列表/读取/检查、草稿、审核记录、不可变候选和人物包 | 不代替本人确认，不执行远端发布 |
| install.py | 完整性检查、暂存、保留旧内容、安装及更新、失败恢复 | 文件成功不等于会话已加载 |
| get.py | 复用干净Git副本或单次获取目标commit；ZIP备用；交事务安装器处理 | 不创建仓库、不push、不获取私人凭据 |
| evaluate.py / judge.py | 真实多轮执行与独立评审，记录原始证据及六维质量分 | 不保证任意回答9分，不代替本人相似度确认 |
| run_suite.py / check_rendering.py | 单入口执行问答、判分与实际Markdown解析检查 | 不静默改写答案，不把脚本成功当内容全部通过 |

## 最小数据结构

| 文件/对象 | 当前主要字段 | 约束 |
|---|---|---|
| person.json | schema_version、person_id、name、current_version、installed_content_sha256、status | ID与版本、快照身份及内容一致，不能用姓名猜测合并 |
| manifest.json | schema_version=2、person_id、name、version、files、source_links、content_reviewed、disclosure.scope | 兼容schema 1；files为knowledge和sources的相对路径与SHA256；拒绝多余、缺失、变更文件 |
| 草稿 | authoring/draft下knowledge、sources及source-links.json | 用户授权修订，不改变既有快照 |
| 审核记录 | 确认类型、文件及指纹、来源对应指纹、范围、说明和时间 | 内容和披露独立；修改指纹后旧确认不能沿用 |
| 能力清单 | .install-manifest.json 中版本与逐文件SHA256 | 本地修改则停止覆盖；不接受源包预置安装清单 |
| 运行记录 | 问题、原始回答、完整事件、退出码、线程、耗时、输入及环境哈希 | 运行成功、语义通过和人工确认分开 |
| 质量判定 | 六维适用性、分数、权重、原文引证、事实门槛和改进项 | Decimal四舍五入；不改标准为高分服务；无效评审不能计入通过 |

当前人物版本为1.1.0，统一事实稿v2.2；本人最新更正1%分母为全部符合开放条件的用户，具体人数未知。本次能力为0.1.13，六份知识保持不变，新增已授权的最终简历原件。历史、设计、离线与新推演分开，不因术语相同合并证据等级。

哈希证明内容一致性，不证明现实身份、来源真实性或无恶意篡改。现实授权仍依赖宿主、可信来源及用户明确行为。首版不声称隔离同机恶意用户。

## 统一 GitHub 链接与跨宿主安装

用户复制仓库链接并提出安装意图。Agent读取[INSTALL.md](../INSTALL.md)，取得完整包、识别当前宿主、安装能力和默认人物、核验文件，再在新会话实际问答。无需用户自行编辑YAML。

| 宿主 | 项目级发现位置 | 配置处理 | 验证要求 |
|---|---|---|---|
| Codex | .agents/skills/interviewtwin | 共用SKILL.md，agents/openai.yaml用于展示 | 主环境实际安装、读取、连续问答与更新 |
| Claude Code | .claude/skills/interviewtwin | 共用标准frontmatter；可选adapters/claude-code.yaml构建专用副本 | 本机未登录，不能声称已完成真实模型验收 |
| WorkBuddy本地代码项目 | .codebuddy/skills/interviewtwin | 共用标准入口；市场导入可用扩展元信息副本 | 用户已明确自行实测；不将项目目录适配当客户端/云端全部兼容 |

`adapters/*.yaml` 是构建输入。`build_host_packages.py` 将其写进对应副本的SKILL.md顶部；宿主不会直接读取我们自定名称的YAML。正文规则仍完全复用。WorkBuddy可额外生成仅能力ZIP供其“上传技能”，该包不带个人资料，不能冒充完整的开箱面试包。

参考Vercel/NVIDIA的通用目录分发方式，但当前主路径不直接把`npx skills add`当完整安装：它一般只处理Skill目录，仓库外置的默认人物还须初始化；同时本项目更新要保留草稿和识别本地冲突。标准格式复用与产品安装闭环分别负责。

安装器使用Python标准库；不额外依赖Node服务。GitHub下载需要相应网络可达，不能假设大陆网络始终畅通。下载失败保持旧安装，审核后的本地ZIP为兜底；它不替代正式在线入口验收。

## 安装、人物更新与能力升级

`install.py --source 包根目录 --home 使用工作区 --host 宿主` 默认安装赵家奇；`--profile ID`选择包内人物，`--no-profile`仅升级能力。

先校验能力与人物源，检查目标本地改动，再获取单写者锁、暂存并复查源哈希；保留旧能力，切换能力与目标人物指针。旧人物快照、草稿及其他人物保留。受控故障恢复只回退本次变更；恢复失败停止后续写入并明确报告。

不自动合并正式内容的任何本地修改，不删除清单绕过检查。支持schema 1和2；未知schema明确拒绝，不实现任意格式迁移。版本号相同但人物内容不同，拒绝覆盖。未声明的附件、符号链接和路径穿越拒绝进入包。

`get.py --repo 实际仓库 --ref 已审核引用 ...` 优先从公开GitHub HTTPS仓库经Git获取，ZIP备用路径，限制下载/解压大小、拒绝链接、穿越及重复项，使用当前已审核的本地安装器，不执行下载包中的安装脚本。首次链接安装由宿主获取并检查整包后调用本地入口；不提供来源不明的curl管道命令。

当前安装状态为 `installed_pending_session_validation`。必须读取实际版本及内容并通过问答，才能报告使用验证。报告保存真实文件与会话结果，不用模型自报版本代替加载证据；原会话热刷新仍后置。

## 创建、审核与发布状态

宿主读取文字、MD/TXT或实际可读附件；twin.py的source保存原件，draft将整理后的UTF-8 Markdown与所选原件纳入独立草稿，不内置OCR。提供摘要、缺口、试问、差异，创建者分别确认内容与公开范围。

审核绑定文件与指纹。候选只纳入同时满足内容/披露确认的文件，实际排除清单可见；有变动则重新审核。`release`生成本地候选，`pack`导出自包含人物包，不执行远端上传。

`local_test`与`shareable`区分范围；赵家奇1.1.0按本人此前明确授权记录为shareable，但最新指令暂停GitHub发布，不执行上传。其他人物的本地测试授权不能沿用赵家奇的授权。生命周期、实际分发和当前安装可用性分别记录，外部上传事实不能靠标记失败抹掉。正式发布后入口验收本轮不执行。

## 评测与自然回答

固定用例先于优化。evaluate.py每组新会话、组内连续追问；只传问题，保留完整工具与回答。judge.py在独立无工具评审中读取事实依据和原始答案，逐项判定并计算六维分数。9分为内部目标，事实错误独立阻断。

run_suite.py串联问答、判分、渲染检查。脚本执行通过不等于内容通过；需查看每题判定。输入与输出目录必须与面试工作区隔离。新追问注明冻结时间与范围，若用于调试就转为回归，不重复宣称盲测。

check_rendering.py用CommonMark解析原始输出，检测普通文本中的未解析加粗标记；代码中的语法示例不误判。短重点加粗、标点外置、短段落和自然口述为通用规则。解析通过只证明Markdown层，宿主视觉仍另验。本次本人接受少量加粗残留作为本地候选已知问题，检查结果不改写。

正常面试不主动播报工具与文件流程，但宿主更高优先级规则可能强制提示；如实保留原始事件，不过滤提示抬分。若展示最终答案副本，须依据宿主原生阶段标记并保留完整原文对应证据。

本人相似度、观点和公开范围由本人确认；非开发者独立创建与纠错须真人参与。合成人物用于机制验证，不能替代真实使用者成功。

## 交付与尚待验证

本地最小包、宿主补充包、完整五项交付材料分别标明内容和SHA256。打包白名单包含清单内已审核原件，排除未授权原件及测试答案；构建后回读ZIP并验证。最终包安装还需新工作区烟测。

GitHub实际发布和正式链接安装、Claude Code登录后的运行、WorkBuddy由用户实测、本人相似度及真人易用性均独立记录。受限项不阻断其余本地工作，也不伪称通过。
