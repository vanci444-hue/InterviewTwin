# B：创建个人分身

## 原始资料与人物版本（本轮生效）

每个人物有自己的原件、草稿和确认版本。上传MD/TXT、PDF、PNG/JPG/JPEG/WebP时，先按原字节归档；粘贴文字保存为UTF-8 TXT再归档。每文件上限20MiB；不能读取的格式先说明，不能将上传成功当作解析成功。其他格式的原件目前不进入自动原件包，可在本人同意后转换成支持格式。原件与整理后的知识分别保留，不用AI改写内容替代用户原件。

- `people/<id>/sources/<sha256>/<原文件名>`：创建者本地归档。重复上传复用同字节对象，同名新文件保留为另一对象。原路径不写入分发清单。
- `people/<id>/authoring/draft/{knowledge,sources}`：知识与本次候选原件；修改知识时默认保留草稿已选原件，明确选择空列表才排除。`source-links.json`记录已核对的来源对应。
- `people/<id>/releases/<version>/{knowledge,sources,manifest.json}`：只包含当前指纹经内容确认和披露确认的文件。原件审核的是文件版本及允许提供的内容，不等于自动认定其中每句都正确。
- GitHub/本地分发源仍为`profiles/<id>/`，安装后进入人物的`releases/`；作者的本地归档不会被整体同步给接收者。通用Skill目录不保存人物简历。

默认面试读取知识，查看简历/依据时显式读取当前人物当前版本的`sources/`。来源对应只是证据关联，不意味着整份知识都来自简历；未覆盖的历史理由不能补造。原件和知识存在冲突时停止认领冲突结论，回到创建者确认，不在接收者面试中自动重写知识。

内容确认、披露确认、实际发布仍独立。未审核原件默认排除，界面必须显示实际纳入/排除列表。被排除的原件名称和本地路径不进入分发来源对应。文件或来源对应变化后，相关审核不能自动沿用。

普通更新整体更新原来源的能力和绑定人物快照，包括随包简历。先核验、再切换版本指针；旧版原件、本地归档、草稿和其他人物不覆盖。正式快照里的简历被本地修改时停止更新；失败时恢复原指针并保留原件。只升级能力时完全不写人物文件。新会话实际读取新版后才报告使用生效。

本轮暂停GitHub发布，不发邮件。公开授权不等于已上传；本地验收不能冒充正式链接验收。


## 输入与最小槽位

创建、补充、拆分知识或调整长期风格前，读取[资料整理规则](organize.md)：从单份profile.md开始，按内容独立性拆分，不能固定六份，也不能用新增文件替换掉完整草稿。


先检查是否已有人物草稿，允许续建或新建独立人物，不用同名覆盖已有 ID。引导用户：“可以粘贴一段介绍，或提供简历、项目材料；先告诉我希望展示的姓名，以及一段最想被了解的经历即可。”不要求用户编写 Skill 指令或数据结构。

首版稳定输入是对话文本、MD、TXT。受支持的图片、PDF由宿主解析；Word等其他格式目前需经本人同意转换成支持的输入格式；先核验实际读取内容，再展示提取摘要。图片辨识不清、PDF 只能读取部分页、链接无权限等需明确说明，并仅索取缺失段落或转成可读文本，不把附件上传当作读取成功。

| 内容组 | 最小可试问要求 | 不足时怎么做 |
|---|---|---|
| 人物身份 | 展示名、独立人物标识 | 必需时询问，不自动冒用已有人物 |
| 经历或项目 | 至少一段可归属本人的经历，职责及范围能辨认 | 可从简短文本开始；缺少日期、数据时不补造 |
| 决策与结果 | 有则记录原话及来源 | 可以先空缺，试问说明覆盖范围 |
| 表达偏好 | 可先用通用自然口述风格 | 试问后调整；不继承其他人物的口头习惯 |
| 来源及确认 | 能对应到提供的内容，标记未确认／确认 | 输入不等于事实已确认或允许公开 |
| 公开范围 | 正式交付前逐组决定提供、脱敏或排除 | 未审核内容不进入正式分发 |

先按内容组展示“已理解内容、未覆盖内容、冲突”，少量信息即可生成试问草稿。不同来源冲突时集中展示具体差异，不机械逐项追问、不选择看起来更漂亮的数字；未解决部分不陈述为事实。

生成资料的展示姓名与资料主体始终使用新人物，不沿用宿主默认用户、赵家奇或其他人物的姓名。需要作者字段时按实际提供者明确填写；合成测试可标“测试驱动”，不得复制默认作者造成身份混淆。

知识正文保存经历、来源、未知和合成测试标记。草稿／候选等会变化的生命周期由工具状态管理，不在正文硬编码“只能草稿试问”。生成候选前检查正文与实际状态一致；保留“合成资料、未经真人确认”等仍然真实的边界，不能把测试驱动确认改写为真人背书。

## 草稿与纠错

将整理结果写入独立草稿，显示当前能回答的范围。草稿试问仍需 A 模式边界。把下列问题分别处理：知识不准确修改知识；知识正确但回答错误修改回答规则或记录问题；表达问题调整风格；披露问题调整交付内容。

修改前展示原文、拟修改及影响摘要；用户确认后写草稿并重新试问，不为一次回答错误破坏正确事实。衍生简介和结论受影响时一并更新，受影响的确认需重做。用户可取消或保留草稿，不能把“已记录问题”当作解决。

## 三次独立决策

1. **内容确认**：按组确认是否真实准确、能否代表本人，记录当前内容与用户明确反馈。未确认或冲突内容可排除，不伪造确认。
2. **公开范围确认**：展示实际交付清单，只含获准材料；脱敏后展示最终文本，排除内容不得随包混入。内容准确不代表允许公开。
3. **发布／交付授权**：检测通过后确认人物、版本、接收范围、目的地和实际内容。准备本地候选包不等于对外发布，未授权不得上传或修改共享权限。

确定性检查绑定本次内容；文件变化后重新检查，相关确认重新取得。阻断项必须修复复测；事实、披露、打包、执行环境问题分别进入对应修复，不全部退回修改知识。

## 交付与退出

本地生成快照、打包、安装验证按操作入口执行。正式入口安装与核心问答验证后才能声明该入口交付成功；当前无远端发布授权时只报告本地候选包和本地验证状态。

验证失败保留原可用版本及记录。内容有问题时停止把该包当作可用入口提供；环境失败时保留已审内容并在环境恢复后重新验证。既有外部分发不会因本地状态失败而自动撤回，需如实报告已执行动作。用户可以随时停止并保留草稿与证据。
