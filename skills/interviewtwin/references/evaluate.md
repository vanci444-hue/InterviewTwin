# D：评测与检测

识别检测对象：人物草稿／正式版本、通用能力、发布前包或实际安装环境。记录人物、能力版本、资料版本与受检文件指纹，说明要执行文件检查、问答评测还是安装更新验证。

## 执行与证据

文件检查通过操作入口执行，保存原始输出。它可检查结构、内容指纹、版本与分发范围，但不能证明个人事实真实或表达像本人。

问答评测使用工作区独立的 `evaluations/` 或开发者测试目录。若当前安装没有评测输入，先说明缺少正式用例，可依据资料提出新的候选输入，经确认后运行；不报告已执行不存在的用例。不得在正常面试中加载题目答案或判分规则；被测会话只读取题目和人物知识。判分在隔离的评估步骤读取依据，不把期待答案注入被测上下文。

完整交付资料中的 `scripts/run_suite.py --home 独立面试工作区 --output 新结果目录` 可依次执行真实问答、独立评审与 Markdown 渲染检查，可用 `--ids` 限定用例。先检查实际脚本帮助与依赖，再执行；最小安装包不含题库或该执行器，不能凭空宣称已跑完整评测。输出与答案不得放在被测工作区。普通用户只需自然语言发起，宿主负责执行命令与解释报告，不要求手写脚本。

真实模型调用保留输入、完整输出、环境、日期、错误和用例 ID。模型额度、网络或宿主执行阻断时标记未执行／执行失败，完成文件检查等不受影响工作。测试运行的合成人物须注明测试身份，不冒充真实人的确认。

## 逐项与汇总

单项状态：通过、未通过、未执行、待本人确认。一次报告可以同时有四种状态；再按当前阶段汇总阻断项、人工待确认及未执行项。

编造个人事实、混淆人物、把设计当历史上线、把未执行测试当通过，以及泄露排除内容属于阻断。不能通过总体平均分或“接受风险”绕过。表达是否像本人、观点能否代表本人、公开范围是否允许由本人确认，自动评分不能代替。

发布前检查与发布后独立安装分别判定：发布后才可执行的验证不伪称为发布前已通过，也不能在其缺失时宣布交付完成。

## 修复与复测

按知识、回答规则、披露、打包、环境分类问题，交 B/C 执行必要授权下的修复。保存实际差异及对应复测，不由评测模式静默修改事实。小规模可全量复测，报告旧版与新版区别。

本人复核可确认指定内容和版本、要求修改、暂无法确认或排除。更新受影响检查状态后重新汇总，不能把单条确认扩大成整份资料通过。

同一问题连续两次修复后仍复测失败，暂停自动修复并保留证据，说明下一步；用户可明确授权继续，或保留进度。不得无人控制地无限优化或重试。真实非开发者易用性测试和本人风格复核若未完成，始终保留待人工确认状态。

完整评测支持 `--person 人物标识 --cases 该人物的专属题库`。题库 metadata 必须声明 persona（姓名），建议同时声明 person_id；评测自动读取已安装人物的当前版本供独立评审，核对身份、版本与文件哈希。其他人物不能套用赵家奇的标准要点；不匹配时停止。问题和标准要点只在评测侧，不能写入人物知识。
