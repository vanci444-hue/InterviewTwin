# InterviewTwin

**把静态简历变成可以持续追问的个人 AI 分身。**

InterviewTwin 是一个个人数字分身 Skill。它基于本人确认的经历、项目资料和表达方式，让面试官通过对话了解一个人：做过什么、为什么这样做，以及面对新问题会如何思考。

项目提供赵家奇的分身供体验，也支持其他使用者通过自己的资料创建独立分身，无需手写 Skill 指令。

## 为什么做这个项目

简历能呈现经历和成果，却很难完整表达一个人的判断过程。

例如，“做过一个 AI 点餐助手”只是一个起点。面试官真正想了解的往往是：

- 当时遇到了什么问题，为什么值得解决？
- 为什么选择这个方案，而不是其他方案？
- 本人具体负责什么，哪些成果有依据？
- 如果条件发生变化，会如何重新做决策？

InterviewTwin 希望让这些信息可以被主动探索。面试官不必按照预设问答阅读材料，可以围绕感兴趣的项目连续追问，也可以通过假设场景观察分身的分析方式。

对创建者而言，它也是一个整理个人经历的工具：将分散的简历和项目材料整理成可核对、可试问、可持续维护的个人知识。

## 可以用它做什么

| 场景 | 使用方式 |
|---|---|
| 面试一个人 | 了解经历、项目、个人贡献与决策过程，围绕回答继续追问 |
| 讨论新问题 | 提出方法论或假设场景，观察分析思路，并区分推演与真实经历 |
| 创建自己的分身 | 提供简历和项目资料，由 Agent 整理草稿，经过试问、纠错和确认后形成个人版本 |
| 维护个人资料 | 补充经历、修正事实、调整长期表达偏好，并保留旧版本 |
| 检查分身 | 核对资料完整性，并通过评测问题检查事实、判断与表达质量 |

## 设计亮点

### 1. 不只复述经历，也呈现判断过程

个人资料不仅记录“做了什么”，还可以包含问题背景、方案取舍、个人职责和结果依据。

面试官可以从一个概括性问题开始，逐步追问到具体决策。分身的目标是呈现本人已确认的思考方式，而不是把简历扩写成一套通用面试答案。

### 2. 把真实经历与现场推演分开

回答个人经历时，以已确认资料为依据；回答假设题时，可以进行专业分析，但不能把推演说成曾经做过的事情。

资料没有覆盖的细节，也不能直接解释为“本人没有做过”。这一边界用于减少两类问题：编造经历，以及因为资料不全而错误否定真实经历。

### 3. 人物资料独立，更新能力时保留个人积累

通用 Skill 负责回答和资料管理方式，人物资料保存每个人的经历与表达特点。

默认人物的初始化材料随 Skill 携带，使用后保存在工作区独立目录。用户自己的分身、草稿、原件和旧版本不放在 Skill 安装目录中，避免随能力更新被覆盖。

### 4. 创建分身不需要懂 Skill 开发

创建过程围绕使用者熟悉的动作展开：

**提供资料 → 整理草稿 → 试问 → 纠错 → 确认内容与可提供范围 → 形成个人版本**

使用者不需要自己设计提示词或编辑配置文件。自动整理只是草稿，不能替代本人确认。

### 5. 用实际回答验证效果

“资料齐全”不等于“回答得好”，“听起来流畅”也不等于“像本人”。

项目分别检查事实准确性、判断依据、表达风格、多轮一致性和未知问题处理，并保留实际输出与失败案例。安装和更新则单独验证，避免用问答评分替代产品可用性检查。

## 怎么体验

### 安装：任选一种方式

#### 方式一：让 Agent 安装

在准备使用的 Agent 中打开目标工作区，发送：

> 安装 https://github.com/vanci444-hue/InterviewTwin 的 Skill。

按宿主提示完成必要授权。安装后可以直接说“使用 InterviewTwin”。人物初始化由 Skill 在安装收尾或首次使用时处理，无须另写安装指令。如果宿主提示需要刷新技能，按提示新建会话即可。

#### 方式二：在终端安装

适用于 macOS / Linux，需要 Git 和 Python 3.10+。

在准备存放项目的目录打开终端，执行下面这条命令。示例安装到 **Cursor**，执行前请确认当前目录没有同名的 `InterviewTwin-installer` 文件夹：

```sh
git clone https://github.com/vanci444-hue/InterviewTwin.git InterviewTwin-installer && python3 InterviewTwin-installer/scripts/get.py --source "$PWD/InterviewTwin-installer" --repo https://github.com/vanci444-hue/InterviewTwin --home "$PWD/InterviewTwin-workspace" --host cursor
```

命令会下载仓库、安装 Skill、初始化默认人物资料，并保存后续更新来源。安装完成后，用 Cursor 打开生成的 **InterviewTwin-workspace** 文件夹，说：

> 使用 InterviewTwin。

如果使用其他 Agent，替换命令最后的 `cursor`：

| Agent | 参数值 |
|---|---|
| Codex | `codex` |
| Cursor | `cursor` |
| Claude Code | `claude-code` |
| WorkBuddy 本地代码项目 | `workbuddy` |

两种方式安装后，都可以通过“更新 InterviewTwin”发起更新。详细要求与故障处理见[安装说明](INSTALL.md)。

### 面试默认分身

项目提供赵家奇的分身，代表项目为餐小美。可以从下面的问题开始：

> 请介绍餐小美，以及你在这个项目中的职责。

继续追问：

> 为什么先做单日规划？当时考虑过哪些其他方案？

也可以提出假设场景：

> 如果重新设计这个产品，你会优先验证什么？为什么？

你可以随时要求缩短回答、展开某个细节，或查看回答依据。

### 创建自己的分身

> 我要创建自己的分身。这是我的简历，请先整理成草稿，让我试问。

随后通过对话补充资料、修正事实，确认哪些内容可以用于回答。创建个人版本不会自动公开你的资料。

### 更新

> 更新 InterviewTwin。

默认更新 Skill 和绑定的随包人物资料，保留自己创建的人物、草稿、原件和旧版本。若只想更新能力，可以明确说：

> 只更新 Skill 能力，保留当前人物版本。

## 项目结构

```text
InterviewTwin/
├── skills/interviewtwin/   # 可安装的 Skill，含默认人物初始化材料
├── profiles/              # 经审核的人物资料维护来源
├── scripts/               # 构建与安装工具
├── tests/                 # 评测集、验证方法与结果
├── docs/                  # 产品设计、架构与使用说明
└── INSTALL.md             # 详细安装与更新说明
```

InterviewTwin 复用宿主 Agent 的模型与工具能力，不提供独立聊天服务。使用需要 Python 3.10+ 及相应的文件、执行权限；不同宿主的安装、发现和加载行为可能不同。
